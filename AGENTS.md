# Development Guidelines

- Write simple, explicit code with clear, descriptive names, favoring readability over cleverness.
- Keep functions focused and reasonably short, separate components by responsibility, and apply SOLID principles only where they improve clarity and maintainability without introducing unnecessary abstractions.
- Handle errors explicitly and fail with useful messages.
- Dont run test unless specified.
- Remove obsolete, duplicate, or unused code, imports, dependencies, configuration, and comments.
- Use Conventional Commits for commit messages, such as `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, and `chore:`.
